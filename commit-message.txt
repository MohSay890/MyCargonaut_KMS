## Main Problems Encountered ##

### 1. Backend Not Available / Database Connection Issues
- The backend could not connect to PostgreSQL due to port conflicts (local vs. Docker) and password mismatches
- Solution: Changed Docker PostgreSQL to use port 5433 and updated application.properties and application-dev.properties to match

### 2. Journeys Not Displayed in Meine Fahrten
- New journeys were saved in the database but did not appear in the frontend
- Cause: The frontend was filtering or only showing mock data, not real backend data

### 3. Edit and Delete Journey Not Working
- Edit was not implemented (just a placeholder alert)
- Delete returned 404 errors because it tried to delete mock data or used the wrong ID

### 4. Date Format Issues
- The backend returned dates in ISO format, but the frontend expected German format, causing input errors

### 5. Profile Picture and Name Sync Issues
- Profile picture upload was not implemented
- Name and avatar were inconsistent between the header and profile page

### 6. Search Not Returning User's Own Journeys
- When searching, journeys created by the user were not shown due to filter or price slider issues

### 7. 403 Forbidden Errors on Request Creation
- POST /api/requests returned 403 because SecurityConfig didn't permit unauthenticated access
- Old backend instance was running with outdated security configuration
- Date format mismatch (DD.MM.YYYY vs YYYY-MM-DD) caused 400 Bad Request errors

## How We Fixed the Problems ##

### 1. Database/Backend
- Ensured only one PostgreSQL instance is running (Docker on 5433)
- Updated backend config files to match Docker settings
- Killed old Java processes and restarted backend with new SecurityConfig
- Fixed date serialization to use ISO format (YYYY-MM-DD)

### 2. Frontend Data Handling
- Removed mock data filtering for journeys; now always loads from backend
- Fixed mapping between backend and frontend models
- Ensured delete and edit actions use real backend IDs and endpoints
- Fixed username field mapping (vorname/nachname instead of firstName/lastName)

### 3. Date Handling
- Added conversion between ISO and German date formats for form compatibility
- Fixed create-request component to send ISO dates to backend

### 4. Profile Handling
- Implemented image upload and removal
- Unified avatar field across all components
- Made header and profile page always show the latest user info

### 5. Search Improvements
- Increased price slider max to avoid filtering out valid journeys
- Added show all journeys option to search, so users can see all Fahrten, including their own
- Added all types of Vehicles so users can find the suitable offer with the suitable Vehicle
- Integrated filtering by additional services that offered from the driver

### 6. Security & Error Resolution
- Added /api/requests/** and /api/request-offers/** to permitAll() in SecurityConfig
- Properly restarted backend to apply configuration changes
- Fixed type mismatches (string vs number) in request detail component
